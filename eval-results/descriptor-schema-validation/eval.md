# Eval Criteria: fail-closed TCR-1 descriptor schema validation
**Domain:** build / security hardening
**Date:** 2026-09-06

## Pass criteria (ALL must be true)

1. **Reproducibility**
   - [ ] `python3 -m unittest -v` passes from the repository root.
   - [ ] The focused regression command is deterministic across repeated runs.

2. **Demonstrability**
   - [ ] A descriptor containing any unbound extra field is rejected by `tcr1_verify.py` with `descriptor has invalid schema` and no success JSON.
   - [ ] Wrong-type or malformed `type`, `uri`, and `sha256` descriptor fields are rejected as invalid schema before artifact verification.
   - [ ] A descriptor generated by `tcr1_interop.py` remains accepted.

3. **Negative test**
   - [ ] On baseline code, the extra-field regression fails because the CLI incorrectly exits zero.
   - [ ] Reverting only the production fix makes the focused regression fail; restoring it makes focused and full suites pass.

4. **User-spec match**
   - [ ] Change adds distinct fail-closed verification utility rather than cosmetic activity.
   - [ ] GitHub identity is `gunawanbud20-coder`, repository is standalone (`fork=false`), live commit and CI are verified.

## Fail criteria (ANY = no-go)

- Existing valid descriptor no longer verifies.
- Critical descriptor verification is mocked.
- Full suite fails or emits warnings/errors.
- Negative test passes without production fix.

- Focused: `python3 -m unittest -v test_tcr1_interop.TCR1InteropTests.test_descriptor_verifier_cli_rejects_noncanonical_descriptor_schema`
- Full: `python3 -m unittest -v`
